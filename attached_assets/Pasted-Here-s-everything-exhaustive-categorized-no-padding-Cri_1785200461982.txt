🔴 Critical / Protocol Completeness
#	What	Why
1	Persistent database	Every server restart wipes all submitted readings. In-memory is dev-only. Need PostgreSQL or SQLite
2	Device token authentication	Authorization: Bearer {token} is accepted but never validated. Anyone can write to the node
3	POST /readings returns 201 not 200	Spec says 201. Currently returns 200
4	Duration + population factors in server HRI	Server's calculate_hri() ignores duration (1h/8h/24h) and population (general/sensitive) that the SDK supports. The two compute different scores for the same data
5	durationS and indoorOutdoor stored but never used	Submitted readings carry these fields but the server ignores them in QC and HRI
6	Geohash precision validation on POST	Server accepts geohash precision < 5, which the spec forbids
🟡 Spec Sections Not Yet Implemented
#	What	Spec Section
7	Privacy framework — SHA-256 hashed person IDs, geohash-5 floor for personal records, k=5 aggregate minimum, cryptographic deletion	§9
8	Federated node sync — how nodes discover each other, exchange readings, and aggregate without a central owner	Core protocol promise
9	DELETE /readings/{id} — spec says deletion must be cryptographically verifiable	§9
10	GET /readings/{id}/verify — integrity check endpoint using stored payloadHash	§2.2
11	Aggregate endpoint — GET /locations/{geohash}/aggregate — min/max/avg HRI over time window, enforcing k≥5 anonymity	§9
12	Community reports — POST /community/reports, GET /community/reports	§5
13	Device registration — POST /devices/register, GET /devices/{uuid}	§5
14	Search endpoint — GET /search?q=city&lat=&lon=&radius=	§5
🟡 SDK Gaps
#	What	Why
15	pyproject.toml / setup.py	Can't pip install bxp-sdk right now. README says you can
16	Async BXPClient (httpx or aiohttp)	The server is async but the SDK is sync-only. Blocks event loops if called from async code
17	Offline queue — buffer readings locally and flush when server is back	Critical for IoT sensors with intermittent connectivity
18	BXPClient.get_readings() / get_latest() don't handle pagination	Only returns first page silently
19	TypeScript/JavaScript SDK	Massive gap. Any web or Node.js developer has nothing to use
20	MicroPython stub	The protocol is aimed at IoT sensors — no embedded target exists
🟡 Server/API Quality
#	What	Why
21	Rate limiting	Zero protection. Anyone can hammer the AQICN quota or flood submitted readings
22	Structured logging	No logs for submitted readings, errors, or API usage. Impossible to debug or audit
23	Input validation	lat/lon not range-checked (lat must be -90–90, lon -180–180). agent values not checked for negative numbers
24	Cursor/offset pagination	GET /readings?limit=50 has no way to get page 2
25	Background startup preload	Currently GET /readings (default) is slow first call — preload the 10 cities on server start
26	AQICN fallback behavior	If token is missing or expired, API silently returns 404 with no explanation. Should return a clear error
27	ETag / If-None-Match caching headers	City data is cached 10 min server-side but clients re-download every time
